## 0. 全景：一次测量的完整旅程

用户点「开始」→ 手机贴桌沿滑 0.2~2 m → 点「结束」。中间发生的事：

```
[校准段] 静止 2 秒 ──→ 估陀螺零偏 + 重力方向基准
[采集段] 100 Hz 持续采样 ──→ 比力(加速度计) + 角速度(陀螺) 两条数据流
[结束后] 离线后处理管线（全程可回放重算）：
    姿态解算 ──→ 去重力 ──→ 一维投影 ──→ 静止检测/ZUPT ──→ 二次积分 ──→ 距离
```

**架构上最重要的一个决定：采集与计算分离。**
采集期只做一件事——把原始数据落盘（CSV）。所有算法在测量结束后对原始数据离线跑。理由：

1. 算法参数必然要反复调，分离后**改参数不用重新滑**（回放模式，调试效率 ×10）
2. 采集期代码极简，不会因为 UI 卡顿丢采样
3. 实时曲线显示走另一条轻量路径（直接画原始值），不影响测量管线

## 1. 阶段〇：三张地图

### 1.1 单位与坐标系

- 加速度计读数单位 **m/s²**，陀螺读数单位 **rad/s**
- **手机坐标系（body 系）**：手机平放、自然朝向时，屏幕向右是 +x、屏幕顶端方向是 +y、出屏幕朝天是 +z。推手机左侧（设备向右滑）→ x 为正；向天空抬 → z = 运动加速度 + 9.81
- **世界坐标系（world 系）**：我们自己定义的参考架：校准时刻的重力方向为 −z（即 +z 指天）。姿态解算的全部意义 = 求一个「手机系 → 世界系」的翻译关系

### 1.2 三个传感器的分工

| 传感器 | 输出 | 它知道什么 | 它不知道什么 |
|---|---|---|---|
| 加速度计 | 比力（运动加速度 − 重力） | **长期**的重力方向（静止时它就是重力计） | 自己的零偏；动起来后重力和运动混在一起分不开 |
| 陀螺仪 | 角速度 | **短期**的旋转变化快又准 | 自己的零偏；绝对朝向（积分会漂） |
| （磁力计） | 地磁方向 | 绝对航向 | 铁桌子/室内钢筋会把它带沟里，本项目**不用** |

**传感器融合的本质**：加速度计和陀螺是两个各有残疾的传感器，互相当对方的矫正器——陀螺帮加速度计在动态中分离重力，加速度计帮陀螺不漂。

### 1.3 误差预算（以 1 m 目标、误差 ≤ 10 cm 计）

| 误差源 | 未治理时 | 治理手段 | 治理后 |
|---|---|---|---|
| 陀螺零偏 → 姿态漂 → 重力泄漏 | 1° 姿态误差 = 0.17 m/s² 假加速度 | 校准段消零偏 + 互补滤波 | 姿态残余 ~0.3° → ~0.05 m/s² |
| 加速度计零偏 | 0.05 m/s² → 3 秒 22 cm（**前提见下方勘误，实际不成立**） | 校准段吸收进重力基准 + ZUPT | 残余 ~0.01 m/s² |
| 白噪声 | ~0.02 m/s²/样本 | 一维投影扔 2/3 + 积分平均 | 速度 ~0.004 m/s 级 → 位置 ~cm 级 |
| ZUPT 没接住的时间项 | — | 首尾强制归零 + 线性漂移扣除 | 摊平成小残余 |

合计落在 5~15 cm——和 spec 的 5%~15% 一致。**每个数字的来历见 docs/research/03。**

> **⚠ 勘误（2026-10-11，来自 `sim/` 合成数据仿真实证，待真机确认）**
> 「加速度计零偏 → 22 cm」这一格的前提不成立。本指南 §2 的校准做法把重力基准取成
> **加速度计静置均值**，于是常值零偏被重新解释成**安装倾角**——两者在水平方向精确抵消。
> 合成数据实测（25 随机种子，中位）：零偏 0 → 0.5 m/s²，误差仅 0.06% → 0.10%。
> 即：零偏不是靠 ZUPT 兜住的，它在**校准那一步就已经被吸收掉**。
> 它真正的危害换了个地方冒出来——**它是第 7 节判据一失灵的元凶**（见 §7 勘误）。
> 同一批仿真也确认 §3「桌面本身极斜也没关系」是对的（安装倾角 40° 时误差仅 0.09%）。

## 2. 阶段一：数据采集

### 做什么

注册两个硬件传感器监听，100 Hz：

```kotlin
val sm = context.getSystemService(Context.SENSOR_SERVICE) as SensorManager
val acc = sm.getDefaultSensor(Sensor.TYPE_ACCELEROMETER)   // 比力
val gyr = sm.getDefaultSensor(Sensor.TYPE_GYROSCOPE)       // 角速度
sm.registerListener(listener, acc, 10_000)   // 单位是微秒：10000 µs = 100 Hz
sm.registerListener(listener, gyr, 10_000)
```

每次回调拿到：`event.values`（3 个数）+ `event.timestamp`（**纳秒**，单调递增，同设备所有传感器共用同一时钟——这是官方保证）。

**落盘格式（CSV，每传感器一个流）**：

```
timestamp_ns, ax, ay, az        ← 加速度计流
timestamp_ns, gx, gy, gz        ← 陀螺流
```

两条流**各自独立回调、采样时刻不重合**（加速度计 12:00:00.010，陀螺 12:00:00.013）。这不是 bug，是现实，姿态解算前要做时间对齐（见阶段三开头）。

### 静止时数据长什么样（建立手感）

```
加速度计:  [0.12, -0.35, 9.79]   ← 不是 [0,0,9.81]！前两个数是零偏+桌面不平
陀螺仪:    [0.008, -0.012, 0.003] ← 不是 [0,0,0]！这是零偏(约 0.5°/s 量级)
```

滑动中（0.8 m / 1.5 s）：滑动方向那根轴会出现 ±1 m/s² 量级的平滑鼓包，其他轴基本不动（理想情况）。

### 数据有什么缺陷（采集层的全部坑）

1. **零偏（bias）**：恒定错误读数，每台机器不同、每次开机不同、温度一变就挪。不校准 → 位置误差平方爆炸
2. **白噪声**：每个样本 ±0.02 m/s² 抖动，单样本看是毛刺，积分不会完全平均掉
3. **采样不均匀（jitter）**：请求 100 Hz，实际回调间隔 5~25 ms 乱跳，还可能偶尔断流 100 ms。所以 **dt 永远用相邻 timestamp 实测差**，永远不要写死 0.01
4. **drop 段**：UI 卡顿/系统调度导致丢样。发现 dt > 50 ms 的段要标记，算法层特殊处理（阶段七）
5. **厂商差异**：有的机器你请求 100 Hz 它给 98 Hz；有的加速度计噪声大 3 倍。**每台真机先跑"体检"**
6. **别用系统软件传感器**：`TYPE_LINEAR_ACCELERATION`（"线性加速度"）、`TYPE_GRAVITY`（"重力"）是厂商黑盒派生的，质量不可控，官方文档明说可用性因设备而异。我们只要两个原始硬件传感器，去重力自己做

### 怎么验证（体检 A：传感器静态体检）

手机静止放桌 30 秒，导出 CSV 检查：

- 模长 ‖accel‖ 应 ≈ 9.81（偏差 >0.3 说明这颗传感器有问题）
- 三轴均值 = 该机的零偏水平（记录下来，机型档案）
- 三轴标准差 = 噪声水平（0.01~0.05 m/s² 都正常，>0.08 这台机器难做）
- 画 timestamp 间隔直方图：应集中在 10 ms，尾巴长说明调度不稳

## 3. 阶段二：校准（开始后 2 秒静止）

### 做什么

用户点「开始」后，UI 显示「保持静止…」倒计时 2 秒，期间采到的数据算两个东西：

1. **陀螺零偏 b_g** = 陀螺读数的均值（3 个数）。为什么能校：静止时角速度真值是 0，读数几乎全数是零偏
2. **重力方向基准 g_body** = 加速度计读数的均值。它进入姿态解算当参考（阶段三）

### 一个微妙但必须懂的事实

**加速度计的零偏校不出来。** 静止时加速度计读数 = 重力向量 + 零偏，3 个方程 6 个未知数（3 重力 + 3 零偏），解不开。我们只能把「重力+零偏」打包当一个基准用，零偏就藏在里面。这就是为什么后面必须靠 ZUPT 兜底——它从边界条件上把这类「恒定假加速度」的线性影响摊平。

### 数据缺陷（校准段的坑）

- 用户手没真静止（说话、桌子被碰）→ 校出来的零偏是错的，全程污染。**防御**：校准段实时检查陀螺范数，超阈值（>0.05 rad/s）就重新计 2 秒
- 刚从口袋掏出，温度冲击中零偏在漂 → 提示用户「手机放稳 30 秒再测」档位（第一版可以不做）
- 桌面本身极斜 → 没关系！重力基准是相对的，世界系的 z 就定义成校准时的重力反方向

### 怎么验证（体检 B）

校准段 2 秒的滑窗均值随时间收敛曲线应平稳（不收敛说明用户在动）。g_body 模长应 ≈9.81 且**和体检 A 的均值一致**。

## 4. 阶段三：姿态解算（互补滤波 + 四元数）

### 做什么（为什么需要）

去重力需要知道手机每个时刻的朝向。朝向用**四元数**表示：4 个数（1 个实部 + 3 个虚部）唯一描述一个 3D 旋转。为什么不直接用三个角（欧拉角）：① 组合旋转有奇异点（万向节锁）② 插值麻烦。你只需要建立两个心智模型：

- **四元数 q = 手机系到世界系的翻译官**：世界向量 = q ⊗ 手机向量 ⊗ q⁻¹（代码里就是一个几十行内的小函数）
- **互补滤波 = 一句话**：最终姿态 = 陀螺的短期贡献（高频可信）+ 加速度计的长期贡献（低频可信）的加权平均

### 算法逐步（每个采样周期执行）

```
输入: 陀螺 ω(已减零偏 b_g), 加速度计 f, 当前 q, 校准时的重力参考 g_body_0

1. 预测（信任陀螺，短期准）:
   q_pred = q ⊗ δq(ω·dt)         ← 把角速度转成小旋转，右乘到 q 上
                                    δq = [1, ωx·dt/2, ωy·dt/2, ωz·dt/2] 再归一化

2. 校正（信任加速度计，长期不漂）:
   g_pred = 用当前 q 把世界重力方向 (0,0,-9.81) 翻译回手机系
   误差方向 e = g_body_0 × g_pred   ← 叉积：两方向之间的"偏差轴"
   （e 的模长 ≈ 重力方向偏差角，它就是姿态误差的体现）

3. 融合（α ∈ [0,1]，典型取 0.02~0.05）:
   q ← 把 q_pred 往修正方向转一小口: q = normalize(q_pred ⊗ δq(−α·e·dt))

输出: 更新后的 q
```

α 的含义：每秒把 α 比例的姿态误差交给加速度计修正。大 α → 跟得快但把滑动加速度当重力抖动吃进来；小 α → 稳但校得慢。**滑动是准静态（加速度 ~1 m/s² vs 重力 9.81），加速度计参考被污染只有 ~10%，这就是我们能用最简单互补滤波的底气**（四旋翼那种大机动才需要 Madgwick/Mahony 级别的东西）。

**时间对齐**在这里做：陀螺和加速度计两条流按 timestamp 最近邻配对（都是 100 Hz，错位 <10 ms，一维场景够用；要更准可用线性插值把加速度计插到陀螺时刻）。

### 数据缺陷（姿态层的坑）

- **yaw（偏航角）不可观**：无磁力计时姿态绕竖直轴慢慢漂——**对我们无影响**，因为一维投影只需要 pitch/roll 剥重力，yaw 漂不碰重力分量。这是本方案不需要磁力计的根本原因
- 滑动中加速度计参考被污染 ~10% → α 不能大
- 陀螺零偏校不准（校准段用户动了）→ 姿态匀速漂 → 重力持续泄漏，表现为结果系统性偏长/偏短
- **振动**（桌面缝、手抖）→ 加速度计瞬间大量程 → 参考完全失效。防御：e 的模长 >0.3 rad 时本帧只信陀螺（跳过校正步）

### 怎么验证（体检 C）

回放模式画三个曲线：

1. 静止 30 s 的 pitch/roll 角：应平坦不漂（漂 = 零偏没校好）
2. 滑动全程 pitch/roll：应在 ±2° 内平滑变化（大变化 = 手在转手机，数据要弃）
3. 用 q 把加速度计原始数据旋到世界系、减重力后（下一阶段输出）：**静止段应 ≈ [0,0,0]**——这是姿态+去重力的联合体检，残差 RMS 就是精度地板，直接量出来

## 5. 阶段四：去重力

### 做什么

两个公式，没有更多：

```
a_world = R(q) · f_body          ← 比力旋到世界系（用姿态翻译官）
a_lin   = a_world − [0, 0, +9.81] ← 减掉重力（z 指天）
```

现在 `a_lin` 是纯运动加速度（世界系）。

### 数据缺陷

这一步**不引入新噪声**，它是放大器：姿态错 1° → 泄漏 9.81·sin(1°) ≈ 0.17 m/s²。去重力质量 = 姿态质量，**没有独立调参空间**——这步出问题回阶段三找。

（也有把重力泄漏当参数在线估计的做法——Kalman 滤波全家桶——对第一版是过度设计，ZUPT 已兜底。）

### 怎么验证

见体检 C 第 3 条。补充一条：滑动中 `a_lin` 应只在水平面内有一个轴活跃、z 轴平静——z 轴有大动静 = 姿态在滑动中坏了。

## 6. 阶段五：一维约束（PCA 找滑动方向）

### 做什么

**PCA（主成分分析）的直觉版**：把整个滑动过程的世界系加速度向量（几百个 3D 点）撒在空间里，它们大致排成一根雪茄——PCA 就是找到这根雪茄的长轴方向 u（数学上 = 加速度协方差矩阵最大特征值对应的特征向量；3×3 特征分解或幂迭代 15 行代码，无需引库）。

然后把每个 3D 加速度投影成标量：

```
a₁(t) = a_lin(t) · u      ← 从此管线是一维的
```

### 为什么这步是白送的

- 垂直两个轴的噪声**整体丢弃**：三轴独立白噪声 → 只留主轴 = 噪声方差砍到 1/3
- 用户滑得稍微歪：加速度在主轴上仍有投影，距离只损失二阶小量（cos θ）

### 数据缺陷

- **来回滑/蹭两下**：点云变两根雪茄，主轴乱指。防御：PCA 前先用静止检测切段，只对"干净的一段"做
- **S 形滑**：主轴偏向对角，cos 损失 <5%，可接受
- λ₁/λ₂（前两特征值之比）是"这真是一条直线吗"的量化指标：<4 弃测，>10 健康

### 怎么验证

画三轴曲线 + 主轴投影叠加图，人眼核对主轴方向和滑动方向一致；打印 λ 比值。

## 7. 阶段六：静止检测与 ZUPT

### 做什么

**静止检测器**（逐样本滑动窗，窗 0.3 s ≈ 30 样本）：

```
静止 ⇔ 窗内 ‖a_lin‖ < 0.12 m/s²  且  ‖ω − b_g‖ < 0.08 rad/s
```

`a_lin` = 阶段四去重力后的**线性加速度**（不是原始比力模长）。若不想依赖姿态，退一步可用
「窗内各轴加速度标准差 < 0.05」。

两条判据的分工：去重力后的线性加速度超阈值 = 在动或被振动；陀螺超阈值 = 在转。两者都绿 → 静止。

> **⚠ 勘误（2026-10-11，来自 `sim/` 合成数据仿真实证，待真机确认）**
> 原判据「`|‖f‖ − 9.81| < 0.2`」在本工况**结构性失效**，因为它对**横向**运动几乎是瞎的：
> ‖f‖ = √(a² + 9.81²)，横向加速度对模长只有**二阶**贡献。要把它顶离 9.81 达 0.2，
> 需要横向加速度到 **1.99 m/s²**；而 0.8 m / 1.5 s 的加速度峰值只有 1.755 m/s²（模长偏离仅 **0.156**）。
>
> 实测代价：起步平缓时（摆线剖面，更像真实手推）判据一**滞后 180 ms → 误差 −13.7%**，
> 一个人吃掉整个 5%~15% 预算；且在**理想无零偏**的传感器上它**完全不触发**——整段被判为静止、
> 管线直接失败（之前它"能用"纯属侥幸：靠零偏把模长顶过阈值，裕度 0.214 vs 0.2）。
> 换成去重力后的 `‖a_lin‖ < 0.12`：滞后降到 10 ms、误差 **+0.02%**；窗内方差判据滞后 30 ms、−0.42%。
>
> 注意滑窗本身**结构上就滞后半个窗长**，所以起点边界最终应换成采样级变化点检测（见 §8 勘误）。

**ZUPT（零速修正）三连**：

1. **首尾归零**：起点速度本就从 0 积分；终点静止段触发时强制速度 = 0
2. **线性漂移扣除**：终点静止触发时算出残余速度 v_err（理论上应为 0，非 0 的部分 = 全程累积误差）。假设误差主要来自恒定假加速度 δa，反推 δa = −v_err / T_motion，从全程扣掉再重积分一次
3. **中途停顿**：检测到中段静止 >0.5 s → 交互层提示「检测到中途停顿，本次测量可能不准」或分段累加（产品决策，第一版建议先提示）

### 阈值的两端坏法（为什么不能拍脑袋定死）

- 太松（加速度阈值取 0.5）→ 减速尾段被误判"静止"→ 速度提前归零 → **系统性偏短**
- 太紧（取 0.05）→ 桌面微振动一直不承认静止 → ZUPT 永不触发 → 漂移裸奔 → 结果随机偏长
- **标定法**：真机录 10 次「滑 + 停 2 秒」，画**去重力后 `a_lin` 的模长**与陀螺范数曲线
  （别画原始比力模长——它对横向运动不敏感，见上方勘误），人眼看静止段数值分布，阈值取分布的
  3σ 边界。没有文献现成数，每台机自己标（先例 Wojtek 也是实验选定）

### 怎么验证（体检 D）

静止检测的 0/1 标记叠加在**去重力后 `a_lin` 模长**曲线上：人眼看标记段是否真静止、滑动段是否真没被标。**这是全管线最值得人眼盯着的一步**。

## 8. 阶段七：二次积分

### 做什么

梯形积分（数值积分最简二阶方法：相邻采样点线性相连求面积）：

```
v[i+1] = v[i] + (a₁[i] + a₁[i+1]) / 2 · dt[i]     ← dt 实测: (t[i+1]−t[i])·1e-9
p[i+1] = p[i] + (v[i]   + v[i+1])  / 2 · dt[i]
距离 = |p[N]|     （起点是 0，终点位置就是距离）
```

为什么不用更高级的积分（如辛普森）：高阶方法靠多项式插值，**噪声被高阶差分放大**。100 Hz 下梯形法本身的截断误差 O(dt²) 已远小于噪声项——升级积分格式等于给噪声买放大器。

### 数据缺陷

- drop 段（dt > 50 ms）：线性插值补样本再积分（匀速段一个 100 ms 的洞影响 <1 mm，其实可忽略；标记出来以防它出现在加减速段）
- ~~ZUPT 归零发生在"检测到静止"的样本上，和物理静止起点差几十 ms → 速度归零位置差几 mm，可忽略~~
  **此句错误，见下方勘误：起点边界必须做到采样级精度。**

> **⚠ 勘误（2026-10-11，来自 `sim/` 合成数据仿真实证，待真机确认）**
> 「差几十 ms → 差几 mm」错了**三个数量级**。实测（真值姿态 + 理想传感器，隔离检测器误差，
> 只挪动积分窗口）：
>
> | 积分起点晚 | 误差 | 积分终点晚 | 误差 |
> |---|---|---|---|
> | 10 ms | **−1.65%** | 10 ms | −0.01% |
> | 50 ms | **−8.22%** | 50 ms | −0.06% |
> | 300 ms | **−46.5%** | 300 ms | −0.66% |
>
> 不对称的原因是物理的：**起点处速度刚从 0 抬起，把 `v=0` 钉晚一点，等于把那段真实速度整段丢掉；
> 终点处速度已经回到 0 附近，多积一段静止段不产生位移。**
>
> 结论：**只有起点边界需要采样级精度，终点可以用粗判据。** 这是全项目真正的精度瓶颈——它比
> 传感器零偏/噪声重要得多（后者在标称参数下只贡献 0.07%，且几乎不被任何参数旋钮推动）。
> 实现建议：起点改用**双阈值滞回**或 **CUSUM 变化点检测**，不要用 0.3 s 滑窗。

### 怎么验证（体检 E）

- v(t)：应从 0 出发、单峰、回 0（两端 ZUPT 后严格为 0）。双峰 = 中途犹豫（减速再加速）；尾部不归 0 = 静止检测没接住
- p(t)：单调上升到平台，平台高度 = 结果

## 9. 阶段八：结果合成

- **单次结果** = |p(T)|，显示时四舍五入到 cm
- **多次测量**：同一物体连测 3~5 次取**中位数**（比均值抗离群），展示极差（max−min）当"测得稳不稳"的提示
- **质量门**（结果显示前自动检查，任一不过就打问号）：
  - λ₁/λ₂ ≥ 4（真的是直线）
  - 首尾静止段各 ≥ 0.5 s（ZUPT 真的发生了）
  - 测量时长 0.5~4 s（超窗误差模型失效）
  - 陀螺全程范数 < 0.3 rad/s（手机没被拎起来转）

## 10. 阶段九：整体调试工作流（回放模式）

**这是开发期最重要的基建**，第一天就做：

1. 每次测量自动 dump 原始 CSV（两条流）到本地
2. App 里一个「回放」入口：选历史 CSV → 跑完整管线 → 显示全套体检图（A~E）
3. 所有算法参数集中在 `PipelineParams` 一个 data class：阈值、α、窗长全在这，改完回放立刻看结果变化

有了回放模式，调参从「每改一个数重新滑一次」变成「滑 10 次存 10 组数据，之后全在桌上调」。

**标定仪式**（真机第一次跑）：

- 找已知长度的东西：A4 纸长边 29.7 cm、量好的桌子 80 cm 等
- 每个长度测 10 次，记录误差 → 出「距离 vs 平均误差」表 → 和 docs/research/03 的理论预算对
- 这张表 = App 的「出厂精度声明」素材

## 11. 术语词典（全文兜底）

| 术语 | 一句话解释 |
|---|---|
| 比力 (specific force) | 加速度计实际输出 = 运动加速度 − 重力；静止时读 +9.81（Z 轴朝天） |
| 零偏 (bias) | 传感器的恒定错误读数，温度和开机状态都会挪它 |
| 白噪声 (white noise) | 每个样本独立的随机抖动，频谱平坦 |
| jitter | 采样间隔不均匀，回调忽快忽慢 |
| 四元数 (quaternion) | 4 个数表示 3D 旋转，无奇异点；本项目只用它的"翻译官"身份 |
| body 系 / world 系 | 手机自身坐标系 / 以校准时重力方向定义的世界坐标系 |
| 互补滤波 | 陀螺(短期可信) + 加速度计(长期可信) 的加权融合，α 是权重 |
| Madgwick / Mahony | 互补滤波的两种工程化升级写法（梯度下降 / PI 控制器），第一版不用 |
| 重力泄漏 | 姿态误差让重力分量混进线性加速度：1° → 0.17 m/s² |
| ZUPT (零速修正) | 用"此处速度必为 0"的物理事实重置积分误差 |
| 线性漂移扣除 | 把终点残余速度反推成恒定假加速度，全程扣掉重积分 |
| PCA (主成分分析) | 找数据最"分散"的方向；这里用来从加速度点云找滑动方向 |
| 特征值比 λ₁/λ₂ | 主轴与次轴能量比，"是不是一条直线"的量化指标 |
| 梯形积分 | 相邻采样点线性相连求面积的数值积分，对噪声友好 |
| VRW / ARW | 速度/角度随机游走：传感器白噪声强度的标准规格写法 |
| Allan 方差 | 静态长时序分析工具，把零偏/噪声/漂移分项测出来 |
| 万向节锁 | 欧拉角表示旋转的奇异缺陷，四元数天然免疫 |
| 体检 A~E | 本指南定义的 5 组标准验证曲线，对应采集/校准/姿态/检测/积分 |
| pitch / roll / yaw | 俯仰(前后倾) / 横滚(左右倾) / 偏航(转头)，姿态的三个口语叫法 |

## 12. 实现顺序建议（防止一口气吃成胖子）
